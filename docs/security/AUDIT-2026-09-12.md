# Auditoría de seguridad — 2026-09-12 (fase Seguridad)

Alcance: todo el backend (`backend/app`), mostrador (`frontend/src`), móvil (`frontend/mobile/src`),
documentación y dependencias. Criterio: corregir lo real; **sin seguridad teatral** que perjudique
la operativa del TPV (FASE_17). Veredicto global: **sin vulnerabilidades críticas ni altas en
producción**; dos acciones aplicadas y un riesgo aceptado documentado.

## Áreas revisadas

| Área | Veredicto | Detalle |
|---|---|---|
| Autenticación | ✅ | Argon2id (argon2-cffi, defaults OWASP); hash señuelo anti-enumeración (`verify_dummy`) en usuario inexistente, inactivo y sin PIN; mensajes de error únicos para todo fallo de credencial; auditoría `auth.login_failed` con razón. |
| Autorización | ✅ | JWT verificado (firma+exp) ANTES de abrir sesión de BD; sesión revocable en caliente (`load_principal` consulta `user_sessions` en cada petición); permisos leídos de BD por petición (revocar un permiso surte efecto al instante). |
| SQL injection | ✅ | Todo el acceso es ORM SQLAlchemy 2.x parametrizado; los únicos `text()` son `SELECT 1` y DDL de índices parciales (constantes). Los informes usan constructs, no strings. |
| XSS | ✅ | Cero `dangerouslySetInnerHTML`/`innerHTML`/`eval` en mostrador y móvil; React escapa por defecto; entradas validadas con Zod antes de usarlas. |
| CSRF | ✅ | La API viaja con `Authorization: Bearer` (no cookie); el refresh va en cookie `HttpOnly`, `SameSite=strict` y `path=/api/v1/auth` (fuera de dev/test, `secure`); cuerpos JSON → preflight CORS exigido para peticiones cruzadas. |
| CORS | ✅ | **Deny por defecto**: con `TPV_CORS_ORIGINS` vacío el middleware ni se monta; si se configura, lista cerrada de orígenes con `allow_credentials` (nunca `*`). En dev, proxy Vite → same-origin. |
| Secrets | ✅ | ADR-008 cumplido: sin credenciales en seeds (solo roles/permisos/impuestos/métodos/parámetros), `.env.example` con placeholders, ningún `.env` en disco, `TPV_JWT_SECRET` obligatorio ≥32 chars (RuntimeError si falta). Secrets de test desechables y rotados. |
| Logs | ✅ | JSON estructurado por stdout con `request_id`; no se registran contraseñas, PIN ni tokens (audit trail en BD registra usuario/acción/IP, nunca el secreto). |
| Sesiones | ✅ | Refresh opaco 256-bit, **solo SHA-256 en BD**; rotación con revocatoria del anterior; reutilizar un refresh revocado cierra el acceso; logout idempotente; cookie con `max_age` = vida del refresh. |
| Rate limiting | ✅ | Ventana deslizante en memoria sobre `login`/`pin` (10 intentos / 60 s por IP+ruta, configurables), 429 con `Retry-After`. Suficiente para LAN de proceso único (§8.3); estado por instancia de app. |
| Permisos | ✅ | RBAC granular (`role_permissions`); el alcance `pos` (PIN) nunca administra: `admin.*` → 403; topics WS con mapa cerrado (desconocidos y `agent:*` denegados; `system` a cualquier autenticado, por diseño). |
| Exposición PostgreSQL | ✅ | ADR-002: solo el servidor habla con la BD; los clientes jamás. Credenciales por `TPV_DATABASE_URL` (env). El hardening de red (listen solo en LAN, `pg_hba`, SSL) se verifica en la fase de Despliegue — fuera de código, sin nada que corregir ahora. |
| Backups | ✅ (diseño) | Estrategia completa en ARCHITECTURE §10 (pg_dump cifrado, retención 7/4/12, restauración ensayada RTO ≤30 min, alerta por `system`). El worker que la ejecuta es una fase propia posterior. |
| Endpoints administrativos | ✅ | 86 rutas: todas las de negocio llevan `dependencies=_permiso` (cash 8/8, catalog 34/34, payments 4/4, printing 8/8, sales 9/9, reports 10/10, documents 6/6); solo son públicas `healthz`/`readyz` (liveness/readiness, sin datos sensibles) y auth (login/pin/refresh/logout, por diseño). |
| WebSocket | ✅ | Primer frame `auth` obligatorio con timeout (10 s); close 4401/4400; sesión de BD corta (abrir-cerrar, nunca retenida); temas sin permiso → `denied` sin cortar conexión; `since_id` validado (entero ≥ 0). |
| Subida de archivos | ✅ | Única vía: logo por JSON base64 (sin multipart en todo el backend): mime whitelist png/jpeg → nombre fijo `logo.{ext}` (sin path traversal), ≤512 KiB, bajo permiso `documents.manage`, con auditoría y evento. |
| Dependencias | ⚠️ aceptado | **Python (pip-audit 2.10.1): sin vulnerabilidades conocidas.** **npm (mostrador): 5 avisos, TODOS en devDependencies** (vite ^5.4.3 HIGH, vitest ^2.1.1 CRITICAL, esbuild, @vitest/mocker, vite-node): no llegan al bundle de producción; el dev server escucha solo en localhost. Los fixes exigen majors breaking (vite 8, vitest 5) → **riesgo aceptado y documentado**; se revisará al subir de major por razones propias. |

## Acciones aplicadas

1. **`.gitignore` en raíz y backend** (no existían): blindan `.env`/`.env.*` (salvo plantilla),
   `backend/data/`, caches y `.venv` contra un futuro `git init` — cumplimiento ADR-008.
2. **Este informe** como registro de la auditoría y del riesgo aceptado de dependencias dev.

## Observaciones sin acción (justificadas)

- Token de acceso en `localStorage`: exposición limitada a 15 min (access corto) y sin vectores
  XSS encontrados; el refresh de larga vida nunca toca JS (cookie HttpOnly). Alternativa (cookie
  Bearer) rompería clientes sin navegador (tpv-agent) — no se cambia.
- Permisos/revocación de sesión en WS se validan al conectar y al suscribirse con el Principal del
  momento; una conexión ya establecida no revalida cada frame (documentado §8; latido la recicla).
- Filas de `user_sessions` caducadas se purgarán con el worker de limpieza (fase propia).
- `/healthz` expone `env` y versión: información mínima necesaria para monitor/instalador en LAN.
