Notas de los escenarios de red (§1.4: el propio api sirve los tres frontends;
Caddy es solo reverse proxy):

- **E21** se define honestamente como *sin Internet con el servidor en pie*:
  todo el tráfico es LAN → healthz 200 sin dependencia externa y las shells
  `/app/movil/` y `/app/tpv/` se sirven igual (el service worker las cachea en
  el navegador, no ejercitable con curl).
- **E22** con el api parado: healthz y shells devuelven 502 del proxy — sin
  servidor no hay shell en red; el navegador aguanta con la copia del SW.
- **E23**: tras reiniciar el api, healthz/readyz 200, login PIN ok, los datos
  persisten (venta 9,65 € paid) y se cobra una venta completa nueva.

E25, matiz de diseño (no bug): con dos cobros simultáneos con la misma
`Idempotency-Key`, el perdedor puede recibir 409 «otra petición está en curso»
(`services/idempotency.py`) en vez del replay instantáneo. Garantía clave
cumplida: **nunca dos tickets**; el reintento secuencial reproduce la respuesta
congelada idéntica.

## 4 · Hallazgos sin corregir (pendientes, no son bugs de lo construido)

- **No existe API de clientes**: el catálogo define permisos
  `customers.view`/`customers.edit` pero no hay endpoints → toda venta va sin
  cliente y la facturación responde siempre 409 «La venta no tiene cliente
  asignado» (visible en E16). Requiere **funcionalidad nueva** (fase futura),
  fuera del alcance de QA.
- El agente de impresión real (`tpv-agent`) sigue pendiente: en E10 el
  despacho/confirm se ejercitó vía API (como haría el agente) con el
  `NullPrinterAdapter` del servidor.

## 5 · Honestidad de cobertura

- Los cuatro arreglos de E10/E21/E22/E23 del recorrido fueron **del arnés**
  (`qa_scenarios.py`: usar token admin para la cola, dispatch previo al
  confirm, límite de cola, división offline/down/recovery), no de la app. Los
  bugs de app de esta fase son los de la tabla §3 (#10 y #11 incluidos).
- E21/E22 con curl no pueden ejercitar el service worker de la PWA (cache de
  shells): eso queda para una prueba manual con navegador.
- Cobro concurrente E25: la carrera se ejercitó con 2 peticiones reales
  simultáneas; no se fuerza contención de BD más allá de esa escala.
